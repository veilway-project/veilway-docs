این صفحه آلفای `v0.2.2-alpha` را نصب می‌کند. فایل‌های آن از [صفحهٔ انتشار هسته](https://github.com/veilway-project/veilway/releases) و [صفحهٔ انتشار پنل](https://github.com/veilway-project/veilway-panel/releases) می‌آیند. برای دیدن آنچه آلفا دارد و جاهایی که هنوز محدود است، ابتدا [نسخهٔ آلفا](../alpha/) را بخوانید.

## چه چیزی لازم است

- یک سرور لینوکسی با systemd، روی معماری x86_64 یا aarch64، که از اینترنت روی درگاه‌هایی که انتخاب می‌کنید در دسترس باشد.
- دسترسی root (با `sudo`) و `curl`. اگر `minisign` نصب نباشد، اسکریپت آن را از مدیر بسته سیستم نصب می‌کند.
- برای پنل: یک نام دامنه که به سرور اشاره کند. اسکریپت می‌تواند وب‌سرور و گواهی آن را برایتان راه بیندازد (بخش [یک وب‌سرور جلوی پنل بگذارید](#یک-وبسرور-جلوی-پنل-بگذارید))، یا می‌توانید وب‌سرور خودتان را بیاورید.

## نصب با اسکریپت

اسکریپت نصب، روش پیشنهادی است. گره، پنل یا هر دو را نصب می‌کند و پیش از نصب، هر دانلود را بررسی می‌کند.

نصب با یک خط:

```
curl -fsSL https://raw.githubusercontent.com/veilway-project/veilway/main/scripts/veilway.sh | sudo bash
```

برای دیدن منو یا اجرای یک دستور، اول فایل را دانلود کنید:

```
curl -fsSL -o veilway.sh https://raw.githubusercontent.com/veilway-project/veilway/main/scripts/veilway.sh
sudo bash veilway.sh
```

گزینهٔ `1` (نصب) را انتخاب کنید، و بعد `node`، `panel` یا `both`. پیش‌فرض `both` است. برای رد کردن منو، دستور `sudo bash veilway.sh install both` را اجرا کنید.

### آنچه نصب روی سرور می‌گذارد

- گره، در `/usr/local/bin/veilway`، و سرویس آن، `veilway.service`.
- پنل، در `/usr/local/bin/veilway-panel`، و سرویس آن، `veilway-panel.service`.
- دو کاربر سیستمی بدون پوستهٔ ورود: `veilway` برای گره و `veilway-panel` برای پنل.
- پوشهٔ پیکربندی `/etc/veilway` و پوشه‌های داده `/var/lib/veilway` و `/var/lib/veilway-panel`.
- یک نسخهٔ پیکربندی نمونه از انتشار، و اگر گره هنوز پیکربندی نداشته باشد، یک پیکربندی اولیه.

### منو

اسکریپت را بدون آرگومان اجرا کنید تا این منو را ببینید:

| کلید | کار | دستور |
|---|---|---|
| 1 | نصب | `install node\|panel\|both` |
| 2 | به‌روزرسانی | `update` (هر دو) |
| 3 | وضعیت | `status` |
| 4 | گزارش‌ها | `logs node` یا `logs panel` |
| 5 | راه‌اندازی مجدد | `restart` (هر دو) |
| 6 | بررسی | `check` |
| 7 | تشخیص | `doctor` |
| 8 | پشتیبان‌گیری | `backup` |
| 9 | بازگردانی | `restore <file>` |
| 10 | حذف | `uninstall` |
| 0 | خروج | |

### دستورها

| دستور | کاری که انجام می‌دهد |
|---|---|
| `install node\|panel\|both\|mirror [--version vX.Y.Z]` | بخش‌های انتخاب‌شده را از آخرین نسخه، یا از برچسبی که می‌دهید، نصب می‌کند. `mirror` یک آینهٔ رله از نقطهٔ پایانی اشتراک را نصب می‌کند، [آینه‌های رله](../manuals/panel/#آینههای-رله) را ببینید. |
| `install panel\|both --domain <name> [--web caddy\|nginx]` | علاوه بر آن، برای آن دامنه یک وب‌سرور با HTTPS راه می‌اندازد، و برای هر مسیری که مال پنل نیست یک سایت ساده. [یک وب‌سرور جلوی پنل بگذارید](#یک-وبسرور-جلوی-پنل-بگذارید) را ببینید. |
| `update [node\|panel\|mirror\|both]` | آخرین نسخه، یا برچسبی که می‌دهید، را نصب می‌کند و سرویس را دوباره راه می‌اندازد. نصب‌کنندهٔ ذخیره‌شده، `/usr/local/sbin/veilway.sh`، را هم با نسخهٔ امضاشدهٔ همان انتشار جایگزین می‌کند، و هرگز با نسخهٔ قدیمی‌تر. دکمه‌های به‌روزرسانی پنل همین کار را برای پنل، گره یا هر دو انجام می‌دهند، [به‌روزرسانی پنل](../manuals/panel/#بهروزرسانی-پنل) را ببینید. |
| `status` | وضعیت هر سرویس، نسخهٔ آن، و پوشه‌های پیکربندی و وضعیت را نشان می‌دهد. نیازی به root ندارد. |
| `logs [node\|panel\|mirror]` | ۱۰۰ خط آخر گزارش سرویس را دنبال می‌کند. |
| `restart [node\|panel\|mirror\|both]` | سرویس را دوباره راه می‌اندازد. راه‌اندازی مجدد گره برای لحظه‌ای همهٔ تونل‌های زنده را قطع می‌کند. |
| `check` | دستور `veilway check` را روی پیکربندی گره اجرا می‌کند. |
| `doctor` | دستور `veilway doctor` را با مسیرهای خود سرویس روی گره اجرا می‌کند. فقط می‌خواند. |
| `backup [file]` | یک فایل `tar.gz` از پیکربندی، وضعیت مصرف گره، داده‌های پنل و پیکربندی آینه می‌نویسد. این بایگانی کلید دارد، و تا وقتی `gateway.next` هنوز روی سرور است آن را هم دارد، پس آن را خصوصی نگه دارید. |
| `restore <file>` | پس از تأیید شما یک پشتیبان را بازمی‌گرداند. فایل‌های فعلی را پیش از آن ذخیره می‌کند. |
| `addon xray [install\|remove\|status]` | افزونهٔ Xray را نصب، حذف یا وضعیتش را نشان می‌دهد. پیش‌فرض `install` است. یک انتشار ثابت از Xray-core رسمی را دانلود می‌کند، و اگر SHA-256 آن با مقدار داخل اسکریپت یکی نباشد آن را رد می‌کند، و فایل اجرایی `xray` را در `/usr/local/lib/veilway/addons/xray` می‌گذارد، با مالکیت root. Xray بعد با کاربر جداگانهٔ `veilway-xray` اجرا می‌شود، و گره وقتی پیکربندی‌اش ورودی Xray داشته باشد آن را راه می‌اندازد. [افزونهٔ Xray](../manuals/xray/) را ببینید. |
| `mirror-sync <folder> [--version vX.Y.Z]` | یک انتشار از گره و پنل را، با امضاهایشان و اشاره‌گرهای امضاشدهٔ `latest`، در پوشه‌ای با همان چینش GitHub کپی می‌کند. هر فایل پیش از ذخیره بررسی می‌شود. پوشه را سرو کنید یا روی فلش ببرید. [نصب از یک آینه](#نصب-از-یک-آینه) را ببینید. نیازی به root ندارد. |
| `uninstall web` | آنچه `--domain` راه انداخته را برمی‌گرداند: فایل سایت، سایت ساده اگر ویرایشش نکرده باشید، مقدار `not_found` پنل، و بسته‌هایی که اسکریپت نصب کرده است. |
| `uninstall` | فایل‌های اجرایی و یونیت‌ها را حذف می‌کند. پیش از حذف پیکربندی و داده‌ها می‌پرسد. پشتیبان‌ها باقی می‌مانند. |
| `version` | نسخهٔ اسکریپت، گره و پنل را چاپ می‌کند. |

پرچم‌ها:

- `--dry-run` می‌گوید چه کاری انجام می‌شد و چیزی را تغییر نمی‌دهد.
- `--yes` (یا `-y`) به همه پرسش‌ها پیش‌فرضشان را جواب می‌دهد.
- `--version <tag>` به‌جای آخرین نسخه، یک برچسب انتشار را انتخاب می‌کند.
- `--allow-downgrade` اجازه می‌دهد `--version` برچسبی قدیمی‌تر از نسخهٔ نصب‌شده بدهد. بدون آن اسکریپت قبول نمی‌کند، و با آن هشدار می‌دهد.
- `--mirror <url>` از یک آینه نصب می‌کند (برای چند آینه تکرارش کنید)، [نصب از یک آینه](#نصب-از-یک-آینه) را ببینید. `--mirror-only` هرگز به GitHub برنمی‌گردد.
- `--domain <name>` و `--web caddy|nginx` یک وب‌سرور برای پنل راه می‌اندازند. پیش‌فرض `caddy` است.

متغیرهای محیطی:

- `NO_COLOR` رنگ‌ها را خاموش می‌کند.
- `VEILWAY_PANEL_PORT` درگاه پنل را تعیین می‌کند. پیش‌فرض `8480` است.
- `VEILWAY_MIRRORS` نشانی آینه‌ها را با فاصله از هم می‌گیرد، و بعد از `--mirror`ها امتحان می‌شوند.

### دانلودهای بررسی‌شده

هر دانلود یک فایل امضای minisign همراه دارد. اسکریپت آن را با کلید عمومی‌ای که داخل خود اسکریپت است بررسی می‌کند و اگر بررسی شکست بخورد، متوقف می‌شود. عبارت امضای معتبر باید برای گره `veilway <tag> <asset>` و برای پنل `veilway-panel <tag> <asset>` باشد، تا امضای یک فایل برای فایل دیگری استفاده نشود. بدون این بررسی چیزی نصب نمی‌شود.

اگر مدیر بسته‌تان `minisign` ندارد، آن را از [minisign.org](https://jedisct1.github.io/minisign/) نصب کنید و اسکریپت را دوباره اجرا کنید.

## راه‌اندازی گره

نصب تازهٔ `install node` اگر فایل وجود نداشته باشد، `/etc/veilway/node/config.json` را می‌نویسد. مالک آن `veilway` و حالت آن `0600` است. پیکربندی اولیه این‌ها را دارد:

- یک خروجی به نام `This server` که از اتصال خود گره خارج می‌شود،
- بدون ورودی، پس هیچ دستگاهی هنوز نمی‌تواند وصل شود،
- بدون کاربر،
- دو قاعدهٔ مسیریابی: یکی ترافیک بین کاربران را رد می‌کند و یکی نشانی‌های خصوصی را.

اسکریپت پیکربندی را با `veilway check` بررسی می‌کند و گره را فقط در صورتی راه می‌اندازد که بررسی بگذرد. اگر بررسی شکست بخورد، گره متوقف می‌ماند و اسکریپت خطا را نشان می‌دهد.

گرهی که ورودی ندارد هنوز کاری نمی‌کند. یک ورودی در پنل اضافه کنید: **گره** و بعد **ورودی‌ها** را باز کنید. پنل کلید خصوصی ورودی را می‌خواهد، و آن را با `veilway genkey` روی گره می‌سازید. [راهنمای پنل](../manuals/panel/) بقیهٔ کارها را توضیح می‌دهد، از جمله کاربران، اشتراک‌ها و انتشار نمایه‌ها.

برای بررسی پیکربندی در هر زمان، دستور `sudo bash veilway.sh check` را اجرا کنید.

## راه‌اندازی پنل

دستور `install panel` فایل `/etc/veilway/panel.json` را فقط یک بار می‌نویسد. فایل موجود هرگز تغییر نمی‌کند. پنل فقط روی `127.0.0.1:8480` گوش می‌دهد، کوکی‌هایش امن (secure) علامت‌گذاری می‌شوند، و مسیر مدیریت آن تصادفی است، مثلاً `/3f9c0a7e21b84d65`. برای جابه‌جا کردن صفحه‌های مدیریت بعداً، `sudo bash veilway.sh panel-prefix [/new-path]` را اجرا کنید.

اسکریپت در پایان نصب، مسیر مدیریت و یک توکن راه‌اندازی یک‌بارمصرف را چاپ می‌کند. برای دیدن دوبارهٔ توکن، این دستور را اجرا کنید:

```
sudo journalctl -u veilway-panel | grep 'Setup token'
```

پنل توکن را فقط تا وقتی چاپ می‌کند که هیچ حساب مدیری وجود نداشته باشد. آن را خصوصی نگه دارید.

### یک وب‌سرور جلوی پنل بگذارید

پنل خودش TLS ندارد، پس یک وب‌سرور باید آن را روی HTTPS عرضه کند. دو راه هست: اسکریپت این کار را بکند، یا خودتان دستی انجامش دهید.

#### راه خودکار

یک نام دامنه را به سرور اشاره دهید (یک رکورد A، و اگر سرور IPv6 دارد یک رکورد AAAA)، بعد `--domain` را اضافه کنید:

```
sudo bash veilway.sh install panel --domain panel.example.com
```

`install both` هم آن را می‌پذیرد. بدون `--domain`، اسکریپتی که در یک ترمینال اجرا شود می‌پرسد وب‌سرور می‌خواهید یا نه، و دامنه را می‌پرسد. با `--yes` هرگز نمی‌پرسد.

`--https-port <port>` سایت HTTPS را روی درگاهی غیر از ۴۴۳ می‌گذارد، برای نمونه `--https-port 8443`. پنل بعد از آن در `https://panel.example.com:8443/<prefix>/` است. درگاه ۸۰ در هر حال باز بماند، چون گواهی از روی آن بررسی می‌شود. هر انتقال TCP گره که روی آن درگاه گوش می‌دهد به ۸۴۴۳ می‌رود (یا به ۸۴۴۴ اگر خود ۸۴۴۳ را انتخاب کرده باشید)، همان‌طور که در مورد درگاه ۴۴۳ پایین‌تر آمده است. اجرای دوباره بدون این گزینه همان درگاهی را نگه می‌دارد که با آن راه افتاده بود.

کاری که روی Debian و Ubuntu انجام می‌دهد:

1. **Caddy را نصب می‌کند**، از بسته‌های خود سیستم اگر نسخهٔ ۲٫۶ یا جدیدتر باشند، وگرنه از مخزن apt خود Caddy با کلید امضای آن. `--web nginx` به‌جای آن nginx و certbot (`python3-certbot-nginx`) را نصب می‌کند.
2. **سایت را در یک فایل جداگانه می‌نویسد.** برای Caddy آن فایل `/etc/caddy/conf.d/veilway-panel.caddy` است، و اسکریپت یک خط، `import /etc/caddy/conf.d/*.caddy`، به انتهای `/etc/caddy/Caddyfile` اضافه می‌کند. Caddyfile‌ای که از قبل دارید همان‌طور می‌ماند، و پیش از آن یک نسخه از آن در `/var/backups/veilway` گذاشته می‌شود. برای nginx فایل `/etc/nginx/conf.d/veilway-panel.conf` است.
3. **دو مسیر پنل را هدایت می‌کند**، یعنی پیشوند مدیریت و مسیر اشتراک را، که از `panel.json` می‌خواند، به پنل روی `127.0.0.1:8480`.
4. **هر جای دیگر یک سایت ساده نشان می‌دهد**: یک صفحهٔ معمولی در `/var/www/veilway-site`، بدون نام یا متن Veilway. ویرایش یا جایگزینی‌اش با شماست و اسکریپت هرگز رویش نمی‌نویسد.
5. **مقدار `not_found` پنل را برابر پاسخ ۴۰۴ خود وب‌سرور می‌گذارد**، تا غریبه‌ها نتوانند مسیرهای پنل را از هر صفحهٔ گمشدهٔ دیگری تشخیص دهند.
6. **گواهی می‌گیرد.** Caddy خودش این کار را می‌کند و تمدیدش هم می‌کند. برای nginx، certbot یک بار این کار را می‌کند و زمان‌سنج خودش تمدید می‌کند. هر دو لازم دارند دامنه به این سرور اشاره کند و درگاه ۸۰ در دسترس باشد. اگر certbot شکست بخورد، اسکریپت می‌گوید و سایت فقط روی http جواب می‌دهد تا `sudo certbot --nginx -d panel.example.com` را اجرا کنید.

اگر از قبل یک وب‌سرور روی سرور اجرا می‌شود، یا چیز دیگری درگاه ۸۰ یا ۴۴۳ را گرفته، اسکریپت پیش از تغییر هر چیزی توضیح می‌دهد و می‌ایستد. هرگز وب‌سروری را که خودش نصب نکرده متوقف یا جایگزین نمی‌کند. اگر Caddy (یا با `--web nginx`، nginx) از قبل اجرا می‌شود، پیش از افزودن فایل و خط import خود می‌پرسد، و `--yes` جواب بله می‌دهد.

**درگاه ۴۴۳ و گره.** گره‌ای که روی درگاه ۴۴۳ انتقال `tls` دارد، درگاهی را نگه داشته که وب‌سرور لازم دارد. انتخاب اسکریپت انتخاب امن است: وب‌سرور ۴۴۳ را می‌گیرد و انتقال‌های TCP گره که روی ۴۴۳ هستند به ۸۴۴۳ می‌روند. اسکریپت اول می‌پرسد (`--yes` بله می‌گوید)، از پیکربندی گره پشتیبان می‌گیرد، پیکربندی تغییرکرده را بررسی می‌کند، گره را دوباره راه می‌اندازد، و اگر چیزی شکست بخورد پیکربندی قبلی را برمی‌گرداند. **نمایه‌هایی که درگاه ۴۴۳ را نام می‌برند کار نمی‌کنند تا آنها را دوباره در پنل منتشر کنید.** طرح دیگر، که گره ۴۴۳ را نگه دارد و وب‌سرور پشت آن باشد، ساخته نشد: گره نمی‌تواند فایل‌های گواهی وب‌سرور را بخواند، چون محدودیت‌های امنیتی سرویس گره و مالک آن فایل‌ها هر دو اجازه نمی‌دهند. برای نگه داشتن گره روی ۴۴۳، از `--domain` استفاده نکنید: وب‌سرور را دستی روی درگاه یا میزبان دیگری بگذارید.

دستور `sudo bash veilway.sh uninstall web` همه را برمی‌گرداند: فایل سایت، خط import، سایت ساده اگر تغییر نکرده باشد، مقدار `not_found` پنل، و بسته‌هایی که اسکریپت نصب کرده. انتقال‌های جابه‌جاشدهٔ گره روی ۸۴۴۳ می‌مانند.

#### دستی

مثال‌ها از `panel.example.com`، مسیر مدیریت `/3f9c0a7e21b84d65` و مسیر اشتراک `/sub` استفاده می‌کنند. از دامنه و مسیر مدیریت خودتان استفاده کنید.

برای nginx، اسکریپت این بلوک را با مسیر مدیریت شما چاپ می‌کند:

```
location ~ ^(/3f9c0a7e21b84d65|/sub)(/|$) {
    proxy_pass http://127.0.0.1:8480;
    client_max_body_size 100m;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
}
```

برای Caddy این را استفاده کنید:

```
panel.example.com {
    handle /3f9c0a7e21b84d65/* {
        reverse_proxy 127.0.0.1:8480
    }
    handle /sub/* {
        reverse_proxy 127.0.0.1:8480
    }
}
```

بعد `https://panel.example.com/3f9c0a7e21b84d65/` را باز کنید، توکن راه‌اندازی را همراه با یک نام کاربری و یک گذرواژه وارد کنید، [شرایط اپراتور](../legal/operator-terms/) را بپذیرید، و [راهنمای پنل](../manuals/panel/) را دنبال کنید. در روش دستی، مقدار `not_found` پنل را برابر صفحهٔ ۴۰۴ وب‌سرور خودتان بگذارید، تا غریبه‌ها نتوانند مسیر اشتراک را از هر مسیر گمشدهٔ دیگری تشخیص دهند.

## نصب از یک آینه

آینه یک کپی از فایل‌های انتشار است روی سروری که مردم به آن دسترسی دارند، برای شبکه‌هایی که GitHub را مسدود می‌کنند. هر کسی می‌تواند یکی راه بیندازد ([میزبانی یک آینهٔ انتشار](../guides/release-mirror/))، و لازم نیست به آن اعتماد کنید: نصب‌کننده هر فایل را با کلید داخل اسکریپت بررسی می‌کند، از هر آینه‌ای که آمده باشد.

```
sudo bash veilway.sh install node --mirror https://mirror.example.org
```

- `--mirror <url>` را می‌شود تکرار کرد. آینه‌ها برای هر دانلود به ترتیب امتحان می‌شوند، و GitHub آخرین چاره است. `--mirror-only` هرگز به GitHub برنمی‌گردد. بدون `--mirror`، `VEILWAY_MIRRORS` (نشانی‌ها با فاصله) همین کار را می‌کند.
- فقط نشانی‌های `https://` کار می‌کنند. `http://` برای `127.0.0.1`، `localhost` و `[::1]` پذیرفته می‌شود، برای آزمایش.
- چینش همان چینش GitHub است: `<mirror>/<owner>/<repo>/releases/download/<tag>/<file>`.
- آینه‌ای که از کار افتاده، مسدود است، یا فایلی می‌دهد که امضایش درست نیست با یک هشدار کنار گذاشته می‌شود و آینهٔ بعدی امتحان می‌شود.
- بدون `--version`، تازه‌ترین برچسب از یک فایل اشاره‌گر امضاشده می‌آید، یعنی `latest-veilway.txt` (برای پنل `latest-veilway-panel.txt`)، که اول از آینه‌ها و بعد از نشانی `releases/latest/download/` در GitHub خوانده می‌شود. اسکریپت اشاره‌گری را که از نسخهٔ نصب‌شده قدیمی‌تر باشد رد می‌کند، پس یک آینهٔ کهنه نمی‌تواند شما را به عقب برگرداند. برچسب قدیمی‌تر از نسخهٔ نصب‌شده نیاز به `--version <tag> --allow-downgrade` دارد.
- انتشارهای پیش از وجود اشاره‌گر، آن را ندارند. اسکریپت آن‌وقت آخرین انتشار را از GitHub می‌پرسد، مگر اینکه `--mirror-only` داده باشید: آنجا از `--version` استفاده کنید.
- افزونهٔ Xray و پیکربندی نمونه هنوز از GitHub می‌آیند.

### اسکریپت را از یک آینه بگیرید

خود نصب‌کننده هم روی آینه هست، امضاشده. پیش از اجرا آن را بگیرید و دستی بررسی کنید. به `minisign` نیاز دارد (`apt install minisign`):

```
curl -fsSLO https://mirror.example.org/veilway.sh
curl -fsSLO https://mirror.example.org/veilway.sh.minisig
minisign -V -m veilway.sh -x veilway.sh.minisig -P RWQiodKlFCiJ3bkZD3ojKV7AYyTYf3F5x/XY8upWvpSFTVm3O2cNRbrV
```

خروجی باید `Signature and comment signature verified` و یک `Trusted comment:` به شکل `veilway <tag> veilway.sh` بگوید. فقط بعد از آن اجرایش کنید:

```
sudo bash veilway.sh install both --mirror https://mirror.example.org
```

اسکریپتی را که از یک آینه گرفته‌اید مستقیم به `bash` پایپ نکنید: اول بررسی‌اش کنید.

### یک پوشه برای سرو یا حمل بسازید

`mirror-sync` همین چینش را از ماشینی که به GitHub (یا آینهٔ دیگری) دسترسی دارد می‌سازد، برای یک وب‌سرور یا یک فلش:

```
bash veilway.sh mirror-sync ./veilway-mirror
bash veilway.sh mirror-sync ./veilway-mirror --version v0.2.2-alpha
```

فایل‌های گره و پنل را با امضاها و اشاره‌گرها دانلود می‌کند، هر یک را پیش از ذخیره بررسی می‌کند، و `veilway.sh` را بالای پوشه می‌گذارد. اشاره‌گر جدیدتری را که از قبل آنجا باشد نگه می‌دارد. صفحهٔ `index.html` قابل مرورِ [`veilway-release-mirror`](../guides/release-mirror/) را نمی‌نویسد.

## نصب با Docker

Docker جایگزین اسکریپت است. ایمیج‌های آلفا در GitHub Container Registry هستند و برای linux/amd64 و linux/arm64 ساخته می‌شوند:

- `ghcr.io/veilway-project/veilway`، گره
- `ghcr.io/veilway-project/veilway-panel`، پنل

هر برچسب انتشار `v*` هر دو ایمیج را با یک برچسب نسخه و `latest` منتشر می‌کند.

پوشهٔ `deploy/compose` در مخزن هسته، گره و پنل را با هم اجرا می‌کند، و یک حجم مشترک برای سوکت کنترل گره دارد. README آن مراحل کامل را دارد، از جمله دستورهای دقیق برای کپی کردن پیکربندی گره و پنل داخل حجم‌ها. به‌طور خلاصه:

1. پیکربندی گره را از `config.example.json` بنویسید. ترنسپورت `ws` داخل کانتینر روی درگاه ۸۴۴۳ گوش می‌دهد، و Compose درگاه ۴۴۳ میزبان را به آن می‌فرستد.
2. کلیدها را با `docker compose run --rm --no-deps --entrypoint veilway node genkey` بسازید.
3. پیکربندی گره و پیکربندی پنل را داخل حجم‌ها کپی کنید، و مالک آن‌ها را uid ‏`65532` بگذارید، که ایمیج‌ها با آن اجرا می‌شوند.
4. فایل `panel.json` را با یک `prefix` تصادفی و `listen` برابر `127.0.0.1:8480` بنویسید.
5. پشته را با `docker compose up -d` راه بیندازید و با `docker compose ps` بررسی کنید. وقتی درگاه ۸۴۸۰ پذیرای اتصال باشد، پنل `healthy` نشان داده می‌شود.

پنل از شبکهٔ میزبان استفاده می‌کند. فقط روی loopback گوش می‌دهد، و loopback یک کانتینر از میزبان قابل دسترسی نیست، پس شبکهٔ میزبان راهی است که میزبان با آن به پنل می‌رسد. مثل بالا یک وب‌سرور با TLS جلوی آن بگذارید.

### نکته‌های Docker

- با `docker compose down -v` حجم‌ها حذف می‌شوند، و آن‌ها کلیدها و وضعیت مصرف را نگه می‌دارند. هنگام توقف پشته، حجم‌ها را نگه دارید.
- فقط یک خروجی `l3` به دسترسی بیشتر نیاز دارد. گره باید به‌عنوان root با `NET_ADMIN` و دستگاه TUN اجرا شود. این خطوط را زیر `node` در `docker-compose.yml` اضافه کنید:

  ```yaml
      user: "0"
      cap_add: [NET_ADMIN]
      devices: ["/dev/net/tun"]
  ```

  خروجی‌هایی که از `netstack` استفاده می‌کنند به هیچ‌کدام از این‌ها نیاز ندارند.
- هر درگاه UDP برای WireGuard در پیکربندی، به یک خط جدا زیر `ports` گره نیاز دارد.

## محل فایل‌ها

| مسیر | محتوا |
|---|---|
| `/usr/local/bin/veilway` | فایل اجرایی گره |
| `/usr/local/bin/veilway-panel` | فایل اجرایی پنل |
| `/etc/veilway/node/config.json` | پیکربندی گره. مالک `veilway`، حالت `0600` |
| `/etc/veilway/config.example.json` | پیکربندی نمونه از انتشار |
| `/etc/veilway/panel.json` | پیکربندی پنل |
| `/var/lib/veilway/veilway-state.json` | وضعیت مصرف گره |
| `/var/lib/veilway/veilway-replay` | حافظهٔ بازپخش گره |
| `/var/lib/veilway-panel/panel.db` | پایگاه داده پنل |
| `/var/lib/veilway-panel/panel.keys` | کلیدهای پنل برای رازهای رمزشده |
| `/var/lib/veilway-panel/signing.keys` | کلیدهای امضای اشتراک |
| `/var/lib/veilway-panel/gateway.keys` | کلیدهای دروازه که درخواست‌های اشتراک را باز می‌کنند |
| `/var/lib/veilway-panel/gateway.next` | نیمهٔ خصوصی کلید دروازهٔ بعدی، تا وقتی آن را از سرور بیرون نبرده‌اید |
| `/etc/veilway-mirror/mirror.json` | پیکربندی آینهٔ رله، اگر نصب کرده باشید |
| `/usr/local/lib/veilway/addons/xray` | افزونهٔ Xray، اگر نصب کرده باشید |
| `/run/veilway/control.sock` | سوکت کنترل گره، با گروه `veilway` |
| `/etc/systemd/system/veilway.service` | یونیت گره |
| `/etc/systemd/system/veilway-panel.service` | یونیت پنل |
| `/var/backups/veilway` | پشتیبان‌ها، و نسخه‌هایی که اسکریپت پیش از بازنویسی یک فایل می‌گیرد |

نسخه‌های نصب‌شده در `/var/lib/veilway/node.version` و `/var/lib/veilway-panel/panel.version` نگه داشته می‌شوند.

:::caution[هنوز نسخه‌ای منتشر نشده است]
هیچ‌کدام از این مراحل منتشر نشده‌اند. اسکریپت و ایمیج‌های Docker فایل‌های نسخه‌ای را دانلود می‌کنند که هنوز وجود ندارند، پس این مراحل تا انتشار اولین نسخه کار نمی‌کنند. این صفحه نصب برنامه‌ریزی‌شده را توضیح می‌دهد.
:::

## چه چیزی لازم است

- یک سرور لینوکسی با systemd، روی معماری x86_64 یا aarch64.
- دسترسی root (با `sudo`) و `curl`. اگر `minisign` نصب نباشد، اسکریپت آن را از مدیر بسته سیستم نصب می‌کند.
- برای پنل: یک نام دامنه و یک وب‌سرور با گواهی TLS جلوی آن.

## نصب با اسکریپت

اسکریپت نصب، روش پیشنهادی است. می‌تواند گره، پنل یا هر دو را نصب کند و پیش از نصب، هر دانلود را بررسی می‌کند.

نصب با یک خط:

```
curl -fsSL https://raw.githubusercontent.com/veilway-project/veilway/main/scripts/veilway.sh | sudo bash
```

برای دیدن منو یا اجرای یک دستور، اول فایل را دانلود کنید:

```
curl -fsSL -o veilway.sh https://raw.githubusercontent.com/veilway-project/veilway/main/scripts/veilway.sh
sudo bash veilway.sh
```

گزینه `1` (نصب) را انتخاب کنید، و بعد `node`، `panel` یا `both`. پیش‌فرض `both` است. برای رد کردن منو، دستور `sudo bash veilway.sh install both` را اجرا کنید.

### منو

اسکریپت را بدون آرگومان اجرا کنید تا این منو را ببینید:

| کلید | کار | دستور |
|---|---|---|
| 1 | نصب | `install node\|panel\|both` |
| 2 | به‌روزرسانی | `update` (هر دو) |
| 3 | وضعیت | `status` |
| 4 | گزارش‌ها | `logs node` یا `logs panel` |
| 5 | راه‌اندازی مجدد | `restart` (هر دو) |
| 6 | بررسی پیکربندی | `check` |
| 7 | عیب‌یابی | `doctor` |
| 8 | پشتیبان‌گیری | `backup` |
| 9 | بازیابی | `restore <file>` |
| 10 | حذف | `uninstall` |
| 0 | خروج | |

### دستورها

| دستور | کاری که انجام می‌دهد |
|---|---|
| `install node\|panel\|both [--version vX.Y.Z]` | بخش‌های انتخاب‌شده را از آخرین نسخه، یا از برچسبی که می‌دهید، نصب می‌کند. |
| `update [node\|panel\|both]` | آخرین نسخه، یا برچسبی که می‌دهید، را نصب می‌کند و سرویس را دوباره راه می‌اندازد. |
| `status` | وضعیت هر سرویس، نسخه آن، و پوشه‌های پیکربندی و وضعیت را نشان می‌دهد. نیازی به root ندارد. |
| `logs [node\|panel]` | ۱۰۰ خط آخر گزارش سرویس را دنبال می‌کند. |
| `restart [node\|panel\|both]` | سرویس را دوباره راه می‌اندازد. راه‌اندازی مجدد گره، همه تونل‌های فعال را برای لحظه‌ای قطع می‌کند. |
| `check` | دستور `veilway check` را روی پیکربندی گره اجرا می‌کند. |
| `doctor` | دستور `veilway doctor` را با مسیرهای خود سرویس روی گره اجرا می‌کند. فقط می‌خواند. |
| `backup [file]` | یک فایل `tar.gz` از پیکربندی، وضعیت مصرف گره و داده‌های پنل می‌سازد. این فایل کلید دارد، پس خصوصی نگه‌دارید. |
| `restore <file>` | پس از تأیید شما، یک پشتیبان را بازیابی می‌کند. پیش از آن، فایل‌های فعلی را ذخیره می‌کند. |
| `uninstall` | فایل‌های اجرایی و یونیت‌ها را حذف می‌کند. پیش از حذف پیکربندی و داده‌ها می‌پرسد. پشتیبان‌ها باقی می‌مانند. |
| `version` | نسخه اسکریپت، گره و پنل را چاپ می‌کند. |

پرچم‌ها:

- `--dry-run` کاری را که انجام می‌شد نشان می‌دهد و هیچ چیز را تغییر نمی‌دهد.
- `--yes` (یا `-y`) به همه پرسش‌ها پاسخ پیش‌فرض می‌دهد.
- `--version <tag>` به‌جای آخرین نسخه، برچسب نسخه مشخصی را انتخاب می‌کند.

متغیرهای محیطی:

- `NO_COLOR` رنگ‌ها را خاموش می‌کند.
- `VEILWAY_PANEL_PORT` درگاه پنل را تعیین می‌کند. پیش‌فرض `8480` است.
- `VEILWAY_PANEL_PUBKEY` کلید عمومی‌ای را که دانلودهای پنل با آن بررسی می‌شوند، جایگزین می‌کند. آن را تنظیم نکنید.

### بررسی دانلودها

هر دانلود یک فایل امضا همراه دارد. اسکریپت آن را با `minisign` و با کلید عمومی‌ای که در خود اسکریپت است بررسی می‌کند. متن «trusted comment» امضا باید `veilway <tag> <asset>` باشد. اگر امضا یا این متن نخواند، اسکریپت متوقف می‌شود و چیزی نصب نمی‌کند.

اگر مدیر بسته شما `minisign` ندارد، آن را از [minisign.org](https://jedisct1.github.io/minisign/) نصب کنید و اسکریپت را دوباره اجرا کنید.

## راه‌اندازی گره

بعد از `install node` روی یک سرور تازه، گره فعال می‌شود اما اجرا نمی‌شود، چون هنوز پیکربندی ندارد. اسکریپت این مراحل را چاپ می‌کند.

۱. کلیدها را با `veilway genkey` بسازید، و آن‌ها را مطابق [مرجع پیکربندی](../reference/config/) در پیکربندی بگذارید.
۲. فایل `/etc/veilway/config.example.json` را به `/etc/veilway/config.json` کپی کنید و آن را ویرایش کنید.
۳. دوباره `sudo bash veilway.sh install node` را اجرا کنید. پیکربندی بررسی می‌شود و گره فقط در صورت موفق بودن بررسی اجرا می‌شود. سپس اسکریپت مالک پیکربندی را `veilway` و حالت آن را `0600` می‌کند.

برای بررسی پیکربندی پیش از آن، دستور `sudo bash veilway.sh check` را اجرا کنید.

## راه‌اندازی پنل

دستور `install panel` فایل `/etc/veilway/panel.json` را فقط یک بار می‌نویسد. فایل موجود هرگز تغییر نمی‌کند. پنل فقط روی `127.0.0.1:8480` گوش می‌دهد، و مسیر مدیریت آن تصادفی است، مثل `/p-0123456789abcdef`.

اسکریپت در پایان نصب، مسیر مدیریت و یک کد راه‌اندازی یک‌بارمصرف را چاپ می‌کند. برای خواندن دوباره کد، این دستور را اجرا کنید:

```
sudo journalctl -u veilway-panel | grep 'Setup token'
```

پنل کد را فقط زمانی چاپ می‌کند که هنوز هیچ حساب مدیری نساخته شده باشد. آن را خصوصی نگه دارید.

### وب‌سرور را جلوی پنل بگذارید

پنل خودش TLS ندارد، پس باید یک وب‌سرور آن را با HTTPS سرویس بدهد. در مثال‌ها از `panel.example.com`، مسیر مدیریت `/p-0123456789abcdef` و مسیر اشتراک `/sub` استفاده شده است. دامنه و مسیر مدیریت خودتان را به کار ببرید.

برای nginx، اسکریپت این بلوک را چاپ می‌کند:

```
location ~ ^(/p-0123456789abcdef|/sub)(/|$) {
    proxy_pass http://127.0.0.1:8480;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
}
```

برای Caddy از این استفاده کنید:

```
panel.example.com {
    handle /p-0123456789abcdef/* {
        reverse_proxy 127.0.0.1:8480
    }
    handle /sub/* {
        reverse_proxy 127.0.0.1:8480
    }
}
```

سپس `https://panel.example.com/p-0123456789abcdef/` را باز کنید و [راهنمای پنل](../manuals/panel/) را دنبال کنید. مقدار `not_found` پنل را برابر صفحه ۴۰۴ وب‌سرور خودتان بگذارید، تا غریبه‌ها نتوانند مسیر اشتراک را از هر مسیر گمشده دیگری تشخیص دهند.

## محل فایل‌ها

| مسیر | محتوا |
|---|---|
| `/usr/local/bin/veilway` | فایل اجرایی گره |
| `/usr/local/bin/veilway-panel` | فایل اجرایی پنل |
| `/etc/veilway/config.json` | پیکربندی گره. مالک `veilway`، حالت `0600` |
| `/etc/veilway/config.example.json` | پیکربندی نمونه از نسخه منتشرشده |
| `/etc/veilway/panel.json` | پیکربندی پنل |
| `/var/lib/veilway/veilway-state.json` | وضعیت مصرف گره |
| `/var/lib/veilway/veilway-replay` | حافظه بازپخش گره |
| `/var/lib/veilway-panel/panel.db` | پایگاه‌داده پنل |
| `/var/lib/veilway-panel/panel.keys` | کلیدهای پنل برای رمزگذاری راز‌ها |
| `/var/lib/veilway-panel/signing.keys` | کلیدهای امضای اشتراک |
| `/run/veilway/control.sock` | سوکت کنترل گره، با گروه `veilway` |
| `/etc/systemd/system/veilway.service` | یونیت گره |
| `/etc/systemd/system/veilway-panel.service` | یونیت پنل |
| `/var/backups/veilway` | پشتیبان‌ها، و نسخه‌هایی که اسکریپت پیش از بازنویسی یک فایل می‌گیرد |

اسکریپت دو کاربر سیستمی بدون پوسته ورود می‌سازد: `veilway` برای گره و `veilway-panel` برای پنل. نسخه‌های نصب‌شده در `/var/lib/veilway/node.version` و `/var/lib/veilway-panel/panel.version` نگه‌داری می‌شوند.

## نصب با Docker

Docker گزینه‌ای جایگزین اسکریپت است. ایمیج‌ها در GitHub Container Registry هستند:

- `ghcr.io/veilway-project/veilway`، برای گره
- `ghcr.io/veilway-project/veilway-panel`، برای پنل

هر دو برای linux/amd64 و linux/arm64 ساخته می‌شوند. هر برچسب نسخه `v*` آن‌ها را با یک برچسب نسخه و `latest` منتشر می‌کند. **هنوز هیچ نسخه‌ای منتشر نشده است، پس این ایمیج‌ها هنوز وجود ندارند.**

پوشه `deploy/compose` در مخزن هسته، گره و پنل را با هم اجرا می‌کند. README آن مراحل کامل را دارد. به‌طور خلاصه:

۱. فایل `config.json` را از `config.example.json` بسازید. ترنسپورت `ws` در کانتینر روی درگاه ۸۴۴۳ گوش می‌دهد، و Compose درگاه ۴۴۳ میزبان را به آن می‌فرستد.
۲. کلیدها را بسازید:

   ```
   docker compose run --rm --no-deps --entrypoint veilway node genkey
   ```

۳. پیکربندی گره و پیکربندی پنل را به volume های آن‌ها کپی کنید، و مالک را uid `65532` کنید، که ایمیج‌ها با آن اجرا می‌شوند. دستورهای دقیق در README آمده‌اند.
۴. فایل `panel.json` را با یک `prefix` تصادفی و `listen` برابر `127.0.0.1:8480` بنویسید.
۵. پشته را راه بیندازید و بررسی کنید:

   ```
   docker compose up -d
   docker compose ps
   ```

   وقتی درگاه ۸۴۸۰ پاسخ دهد، پنل `healthy` نشان داده می‌شود.

پنل از شبکه میزبان استفاده می‌کند. پنل فقط روی loopback گوش می‌دهد، و loopback یک کانتینر از میزبان قابل دسترسی نیست، پس شبکه میزبان ساده‌ترین راه برای رسیدن میزبان به آن است. مانند بالا، یک وب‌سرور با TLS جلوی آن قرار دهید.

### نکته‌ها

- دستور `docker compose down -v` volume ها را پاک می‌کند، و آن‌ها کلیدها و وضعیت مصرف را نگه می‌دارند. هنگام متوقف کردن پشته، volume ها را نگه دارید.
- فقط یک خروجی `l3` به دسترسی بیشتری نیاز دارد. گره باید با root و `NET_ADMIN` و دستگاه TUN اجرا شود. این خطوط را زیر `node` در فایل `docker-compose.yml` اضافه کنید:

  ```yaml
      user: "0"
      cap_add: [NET_ADMIN]
      devices: ["/dev/net/tun"]
  ```

  خروجی‌هایی که از `netstack` استفاده می‌کنند، به هیچ‌کدام از این‌ها نیاز ندارند.
- هر درگاه UDP برای WireGuard در پیکربندی، باید یک خط جدا زیر `ports` گره داشته باشد.
- برای ساختن ایمیج گره از کد، در مخزن هسته `docker build` را اجرا کنید. Dockerfile پنل، هسته و سیستم طراحی را در ارجاع‌هایی که در `VEILWAY_REF` و `VEILWAY_UI_REF` می‌دهید، کلون می‌کند.

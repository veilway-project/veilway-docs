آینهٔ انتشارها پوشه‌ای از فایل‌های انتشار Veilway است، روی وب‌سرور خودتان. مردمی که شبکه‌شان GitHub را مسدود می‌کند، به‌جای آن از این آینه نصب و به‌روزرسانی می‌کنند. هر کسی می‌تواند یکی بسازد و لازم نیست به شما اعتماد کنند: هر فایل را کلید انتشار Veilway امضا کرده است، و اسکریپت نصب و برنامه‌ها خودشان امضا را بررسی می‌کنند.

```text
 GitHub  ---- sync (hourly) ---->  mirror folder  ---- web server ---->  users
 (or another mirror)               (checked files)                       (installer, apps)
```

## چه وقت آینه بسازیم

یک آینه بسازید وقتی کسانی را می‌شناسید که شبکه‌شان GitHub را مسدود یا کند می‌کند، اما می‌توانند به نشانی‌ای از شما برسند: یک VPS کوچک، یک سطل ابری، یا سرور یک دانشگاه یا دفتر کار. چند گیگابایت فضای دیسک می‌گیرد و تقریباً پردازندهٔ کمی مصرف می‌کند. اگر کاربرانتان به GitHub دسترسی دارند، آینه لازم نیست.

## آینه چه می‌تواند و چه نمی‌تواند بکند

- **هیچ چیز را نمی‌تواند تغییر دهد.** فایل تغییرکرده امضایش را از دست می‌دهد. امضا نام محصول، برچسب انتشار و نام فایل را هم دارد، پس فایل واقعی با نام یا برچسب اشتباه هم رد می‌شود.
- **کسی را نمی‌تواند به عقب برگرداند.** اشارگر `latest` امضا شده است. برنامهٔ آینه اشارگری قدیمی‌تر از آنچه دارد نمی‌پذیرد، و کلاینت‌ها هم اشارگری قدیمی‌تر از نسخهٔ در حال اجرای خودشان را نمی‌پذیرند.
- **می‌تواند از کار بیفتد یا کند باشد.** این تمام کاری است که یک آینهٔ بد می‌تواند بکند، پس کلاینت‌ها ممکن است چند آینه بشناسند.
- **می‌تواند بفهمد چه کسی دانلود می‌کند.** وب‌سرور شما می‌بیند کدام نشانی‌ها کدام فایل‌ها را و چه زمانی می‌خواهند. برنامهٔ آینه هیچ گزارش دسترسی نگه نمی‌دارد. nginx و Caddy به‌طور پیش‌فرض گزارش نگه می‌دارند، پس مثال‌ها آن را خاموش می‌کنند. یک CDN بر پایهٔ شرایط خودش ثبت می‌کند. به کاربرانتان بگویید چه چیزی نگه می‌دارید.

## راه‌اندازی آینه

به برنامهٔ `veilway-release-mirror` نیاز دارید، از [مخزن پروژه](https://github.com/veilway-project/veilway-release-mirror). مراحل یک سرور لینوکسی با systemd و یک نام دامنه که به آن اشاره می‌کند را فرض می‌کنند.

1. برنامه را بگیرید: یک فایل اجرایی انتشار برای لینوکس x86_64 یا aarch64، یا تصویر Docker که از `Dockerfile` مخزن ساخته می‌شود. فایل اجرایی را در `/usr/local/bin/veilway-release-mirror` بگذارید.
2. یک کاربر و یک پوشه بسازید: `useradd --system veilway-mirror`، سپس `install -d -o veilway-mirror /var/lib/veilway-mirror`.
3. پوشه را یک بار پر کنید: `sudo -u veilway-mirror veilway-release-mirror sync --out /var/lib/veilway-mirror`. برای هر فایلی که ذخیره می‌کند یک خط چاپ می‌کند. سه انتشار تازهٔ گره و پنل را نگه می‌دارد، به‌علاوهٔ انتشاری که اشارگر امضاشده نام می‌برد.
4. تازه نگهش دارید. پوشهٔ `examples/` مخزن فایل‌های `veilway-release-mirror-sync.service` و `.timer` را دارد که همگام‌سازی را هر ساعت اجرا می‌کنند. هر دو را به `/etc/systemd/system/` کپی کنید و `systemctl enable --now veilway-release-mirror-sync.timer` را اجرا کنید.
5. پوشه را سرو کنید، به یکی از دو روش:
   - `veilway-release-mirror serve --dir /var/lib/veilway-mirror --listen 127.0.0.1:8080` (سرویس نمونهٔ `veilway-release-mirror.service` آن را اجرا می‌کند)، با nginx یا Caddy جلویش برای TLS. نمونه‌ها `examples/nginx.conf` و `examples/Caddyfile` هستند.
   - یا اجازه دهید هر وب‌سرور یا CDN پوشه را به‌عنوان فایل ایستا سرو کند. فایل‌ها را دست‌نخورده سرو کنید، از درخواست‌های range برای فایل‌های بزرگ پشتیبانی کنید، و پوشهٔ `.partial` را سرو نکنید.
6. `https://your-domain/` را در مرورگر باز کنید. صفحه هر انتشار و هر فایل را فهرست می‌کند.

با Docker همان کار در سه دستور انجام می‌شود: `docker build -t veilway-release-mirror .`، سپس `docker run --rm -v veilway-mirror:/data veilway-release-mirror sync --out /data` (از یک تایمر)، و `docker run -d -p 127.0.0.1:8080:8080 -v veilway-mirror:/data:ro veilway-release-mirror` برای سرور.

## آینه از آینه

`sync --from https://other-mirror.example.org` فایل‌ها را به‌جای GitHub از آینهٔ دیگری می‌گیرد. `--from` را چند بار تکرار کنید تا چند منبع داشته باشید، که برای هر فایل به ترتیب امتحان می‌شوند. `--from github` را آخر بگذارید تا در صورت نیاز به خود GitHub برگردد. آینه‌ای که از آن رونوشت می‌گیرید لازم نیست مورد اعتماد باشد: هر فایل پیش از ذخیره با کلیدی که در برنامه تعبیه شده بررسی می‌شود.

اگر پوشه‌ای را روی فلش گرفته‌اید، `veilway-release-mirror verify --dir <folder>` همه‌اش را بررسی می‌کند و هر فایلی را که رد شود فهرست می‌کند. با `minisign` ساده:

```sh
minisign -V -m veilway.sh -x veilway.sh.minisig -P RWQiodKlFCiJ3bkZD3ojKV7AYyTYf3F5x/XY8upWvpSFTVm3O2cNRbrV
```

خط `Trusted comment:` در خروجی باید `veilway <tag> veilway.sh` باشد، که `<tag>` برچسب انتشار پوشه‌ای است که بررسی می‌کنید.

## مردم از آینهٔ شما چطور استفاده می‌کنند

نشانی‌تان را به آن‌ها بدهید. `veilway.sh` گزینهٔ `--mirror <url>` را می‌گیرد و از آن نصب و به‌روزرسانی می‌کند ([نصب از یک آینه](../../getting-started/#نصب-از-یک-آینه)):

```sh
curl -fsSL https://your-domain/veilway.sh | sudo bash -s -- --mirror https://your-domain
```

اسکریپت نصب هر فایل را، از هر جایی که آمده باشد، با کلید تعبیه‌شده‌اش بررسی می‌کند. `veilway.sh mirror-sync <folder>` همان پوشه را بدون برنامهٔ آینه می‌سازد، برای فلش.

## چه چیزی در پوشه است

```text
veilway-project/veilway/releases/download/<tag>/<file> and <file>.minisig
veilway-project/veilway-panel/releases/download/<tag>/<file> and <file>.minisig
veilway-project/<repo>/releases/latest/download/latest-<repo>.txt and .minisig
latest-veilway.txt, latest-veilway-panel.txt (copies of the two pointers)
veilway.sh and veilway.sh.minisig (the installer of the newest release)
index.html, index.json
```

طرح فایل‌ها همان طرح GitHub است، پس نشانی آینه در هر جا که نشانی پایهٔ انتشار GitHub پذیرفته شود، کار می‌کند.

## محدودیت‌ها

- فایل‌های بدون `.minisig` آینه نمی‌شوند. فایل `latest.json` برنامهٔ دسکتاپ یکی از آن‌هاست، پس برنامه‌های دسکتاپ فعلاً از GitHub به‌روز می‌شوند.
- انتشاری که هنوز اشارگر امضاشدهٔ `latest` را ندارد، به‌جای آن از فهرست API گیت‌هاب آینه می‌شود، و آینه در این حالت اشارگر خودش را ندارد. برنامه وقتی این اتفاق بیفتد آن را اعلام می‌کند.
- دو همگام‌سازی را هم‌زمان روی یک پوشه اجرا نکنید.
- آینه فقط به اندازهٔ نشانی‌اش در دسترس است. اگر نشانی‌تان مسدود شود، آینه هم مسدود است: یک آینهٔ دوم داشته باشید.
